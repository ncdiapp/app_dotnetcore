# ImportPLMSearchView — Multi-Agent child prompts

This folder is the Agent Management pack for **two** Deterministic children. It is derived from the three Cursor runbooks in the parent folder — it does **not** replace them.

| Cursor IDE (parent) | Multi-Agent child | SkillKey |
|---------------------|-------------------|----------|
| `PROMPT.md` + `PROMPT_SIBLING_VIEW.md` + `source/MULTI_VIEW_COVERAGE.md` | `Prompt_plm-integration-search.txt` | `plm-integration-search` |
| `PROMPT_MASSUPDATE_VIEW.md` | `Prompt_plm-integration-massupdate.txt` | `plm-integration-massupdate` |

Contract: `AppAI.Web/TenantAgentSeeds/PlmIntegrationMultiAgent/CHILD_AGENT_CONTRACTS.md` (Wave 2). There is **no** `plm-integration-sibling` SkillKey. Additional display View is the same search child (`mode=additional-view`). Never say "sibling" to the end user.

HITL stays on ROOT (`plm-integration-orchestrator`). These prompts treat Phase A checklists as **shared-context output**, not `ask_user`.

## Layout

```text
MultiAgent/
  README.md
  Prompt_plm-integration-search.txt
  Prompt_plm-integration-massupdate.txt
  source/                         ← seed into chat source/ (or AgentStarter/{skillKey}/)
    _plm_probe_search.sql
    _plm_probe_massupdate.sql
    _app_probe_fieldmapping.sql
    _app_probe_search_context.sql
    7_PlmSearch_ImportBlueprint.example.json
    8_PlmSearch_SiblingView.example.json
    9_PlmSearch_MassUpdateView.example.json
    9b_PlmSearch_MassUpdateView_ListEdit.example.json
    plmSearchImportConfig.example.json   ← DataSourceId fields added for App Agent
    MULTI_VIEW_COVERAGE.md
    README.md
```

Official probe SQL and example JSON are **copies** of parent `../source/` (except the config example, which adds `plmDataSourceId` / `appDataSourceId`). Do not regenerate them in a chat. Phase B Blueprints (`1_` / `2_` / `3_` under `output/{id}/`) **are** generated by the child each run (~8–16 KB).

Product auto-seeds these files into chat `source/` and `AgentStarter/{skillKey}/` when the ROOT or child run starts (`GenericAgentOfficialSourceSeedBL`). Users must **not** upload probe/example scripts. After changing `ApplyAgentOutputPlan`, rebuild `APP.AgentPlugins.PlmImport` and restart AppAI.Web so APPLY can run Search/MassUpdate kinds.

## Inputs (ROOT writes shared context)

Search child: PLM DataSourceId + APP DataSourceId + one `searchTemplateId`. Additional View also needs `referenceViewId` (and preferably `appSearchIntegrationId`).

MassUpdate child: same two DataSourceIds + `searchTemplateId` + `massUpdateViewId`.

No connection strings. No user-uploaded scripts.

Tenant seed (Wave 2): `AppAI.Web/TenantAgentSeeds/PlmIntegrationMultiAgent/09_Seed_PlmIntegrationSearch_Child.sql` and `10_Seed_PlmIntegrationMassUpdate_Child.sql`. APPLY uses `apply_agent_output_plan` with `outputsContextKey`.

## PHASE (same shape as import-dw)

`A` (probe + checklist) → ROOT HITL → write `plan` → `B` (Blueprint + `executionPlan`) → ROOT Apply → `APPLY` (`apply_agent_output_plan`).
