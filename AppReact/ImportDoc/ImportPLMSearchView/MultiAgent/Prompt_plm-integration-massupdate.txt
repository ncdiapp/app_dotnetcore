## Conceptual map

```text
pdmSearchTemplate
  ├─ ReferenceViewID              → display grid (already imported by search child)
  ├─ DefaultMassUpdateViewId      → default MU
  └─ pdmSearchTemplateReferenceView
        ├─ ReferenceViewID        → additional display Views (search child)
        └─ MassUpdateViewID       → THIS child

  ├─ UpdateType   1=TabField  2=RegularGrid  3=DynamicMatrix
  ├─ MainTabId / GridBlockId
```

| PLM | APP |
|-----|-----|
| `pdmMassUpdateView` | New `AppSearchView` `IsMassUpdateView=true`, **same** DataSet as the Search |
| UpdateType TabField (flat header) | **Mode A** `SingleTableUpdate` — MasterDetail Transaction + Unit |
| RegularGrid / Matrix (1:N) | **Mode B** `HierarchicalTableUpdate` — ListEdit (root PK only on SearchView) |
| Field SubItem / GridColumn | `AppSearchViewField.MassUpdateTransactionFieldId` (A) or ListEdit unit fields (B) |
| MainTab / update table | `UpdateTransctionId` + `UpdateBaseTranscationUnitId` |
| Result-row Open | Copy `AppFormLinkTarget` from default **display** View |

Runtime type is derived from Transaction (`MasterDetail` → SingleTable; `List` → Hierarchical).

## PHASE=A — Discovery

**Tool rule:** `execute_sql` with matching `dataSourceId`. No claimed rows without tool_result.

### A1. APP Search + candidates (`appDataSourceId`)

Resolve Search. Load DataSet QueryText, existing Views (`IsMassUpdateView`, `UpdateTransctionId`).

If this MassUpdateView is already imported → `ok=true` nothing-to-do (unless `inputs` asks update).

MasterDetail candidates: `Tab_{MainTabId}` and FieldMapping-backed header tables.  
ListEdit candidates: `AppTransaction.TransactionOrganizedType = 3` whose units touch MU header / grid tables.

### A2. PLM Mass Update (`plmDataSourceId`)

Run `source/_plm_probe_massupdate.sql` with `@SearchTemplateId` + `@MassUpdateViewId`.

| Check | Detail |
|-------|--------|
| Shell | Name, UpdateType, MainTabId, GridBlockId, flags |
| Link | Attached via `pdmSearchTemplateReferenceView` and/or `DefaultMassUpdateViewId` — warn if not linked |
| Fields | SubItemId / GridColumnId, Sort, IsReadonly, display names |
| Enrich | SubItem → Tab / Entity; GridColumn → GridMeta / Entity |

APP resolve via FieldMapping. Mode A: prefer `Tab_{MainTabId}`; Unit = table owning most updatable fields; PK must resolve.

Mode B (RegularGrid / DynamicMatrix / RequiresOneToN):

1. Score existing ListEdits (root/child `SysTableName` vs MU tables).
2. Put ranked list in `phase-a.listEditCandidates`.
3. If none → draft **CreateNew** structure from FieldMapping + MU fields (root = header grain, child = 1:N grid). Put in `phase-a.proposedListEdit`. Do **not** write Blueprint yet.

Classify each MU field:

| Class | Meaning |
|-------|---------|
| `MappedToTxnField` | FieldMapping + matching `AppTransactionField` on chosen Unit |
| `CoveredInDataSet` | Already in DataSet SELECT |
| `AddColumn` | Table joined; add SELECT |
| `AddOneToOneLeftJoin` | Extra 1:1 LEFT JOIN |
| `RequiresOneToN` | Forces B |
| `Unmapped` | No FieldMapping |
| `ReadonlySkip` | PLM IsReadonly — display only |

### A3. Report for ROOT (do not wait)

```text
Mass Update View import analysis
PLM SearchTemplateId / MassUpdateViewId / UpdateType / MainTabId
PLM DefaultMassUpdateViewId — this view default? yes|no
APP Search / DataSet
Recommended APP mode: SingleTableUpdate | HierarchicalTableUpdate | Blocked
Proposed Update Transaction / Unit / PK
Field coverage counts
ListEdit candidates (B)
Proposed CreateNew structure (B2) — CONFIRM before Phase B
```

Recommendation:

| PLM UpdateType | Prefer |
|----------------|--------|
| TabField, majority on one header Unit | **A** |
| RegularGrid / DynamicMatrix / RequiresOneToN | **B** + ListEdit discovery |
| B + matching ListEdit | Recommend **B1** (ROOT picks which) |
| B + no ListEdit | Propose **B2**; ROOT must approve structure |
| Mixed header + grid | A for header-only subset, or B if grid is the point |
| Unmapped grid / no PK-FK path | **C** |

## PHASE=B — Generate Blueprint

Always: `mode` = **`MassUpdateViewAttach`**.  
File: `output/{searchTemplateId}/3_PlmSearch_MassUpdateView_{MassUpdateViewId}.json`

Do **not** rewrite Search criteria. Do **not** create a second Search. Do **not** change display default View.

### Option A — SingleTableAttach

Schema: `source/9_PlmSearch_MassUpdateView.example.json`

- `massUpdate.appMode`: `SingleTableUpdate`
- `dataSetPatch` — 1:1 LEFT JOIN only
- `searchView.isMassUpdateView`: true; fields with `massUpdateTransactionFieldId` / `massUpdateDatabaseFieldName` when updatable
- **Must include Unit PK** mapped
- `linkTargets.copyFromDefaultSearchView`: true unless `plan` overrides
- `setAsDefaultMassUpdateView` from plan / PLM default

### Option B1 — existing ListEdit

Schema: `source/9b_PlmSearch_MassUpdateView_ListEdit.example.json`

- `massUpdate.appMode`: `HierarchicalTableUpdate`
- `listEditCreate.action`: `UseExisting`
- `listEditCreate.existingIntegrationId` / `existingTransactionId` from `plan`
- SearchView maps **root PK only**
- Other MU columns live on ListEdit units, not full SearchView MU maps
- DataSet enrich only if root PK / filter columns missing (1:1)

### Option B2 — CreateNew ListEdit

Requires `plan.listEdit.create` (approved).

- `listEditCreate.action`: `CreateNew`
- `integrationId`: `ListEdit_MU{MassUpdateViewId}_{ShortName}`
- `transactionOrganizedType`: `List` (3)
- `unitStructure.root` + `children` from approved plan
- Fields from PLM `pdmMassUpdateViewField` via FieldMapping:
  - `sort` = PLM Sort
  - `isVisible` = false when PLM `IsHide=1` (structural PK/FK always hidden except root identity exception)
  - `isReadOnly` = PLM IsReadonly
  - `controlType` / `entityIntegrationId` from FieldMapping
  - Columns not in the MU field list → hidden
  - **Root identity exception:** always show ReferenceId (or unit PK). Also show Product Code / Description aliases when those fields exist (`Article`, `ProductCode`, `Product_Code`, `ItemCode`, `TrimCode`, `StyleCode`, …). Do not invent missing columns.
- `massUpdate.updateTransactionIntegrationId` = the new ListEdit IntegrationId
- Dedicated ListEdit — never flip an existing `Tab_*` to List

### Option C

No files. `ok=false` + blockers.
