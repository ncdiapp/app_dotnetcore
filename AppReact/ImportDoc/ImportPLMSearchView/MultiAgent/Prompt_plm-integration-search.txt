## Hard rules (domain)

| Rule | Detail |
|------|--------|
| **Prerequisite** | Template DW import done: `{prefix}FieldMapping` exists on APP. Else `ok=false`. |
| **No server code** | Deliverables are JSON under `output/`. BL gap → still write Blueprint, set `ok=false` / warn in `errors` if Execute tools are missing. |
| **Do not copy PLM BlQuery** | `pdmBLQuery.SqlText` is reference only. Synthesize DataSet from JOIN plan + FieldMapping. |
| **Criteria ≠ View** | Score JOIN plans separately for criteria coverage and view coverage. |
| **Grid 1:N** | `FieldKind = GridColumn` default `gridColumnStrategy = exclude`. Alternatives: `scalar` (TOP 1 subquery), `accept-1N` (only if `plan` says so). |
| **Additional View Option A** | May add SELECT columns and/or **first-level 1:1** `LEFT OUTER JOIN` on `ReferenceId` / header key. **Forbidden:** 1:N grid joins that multiply rows. |
| **Cross-grain → B** | Header×grid row multiplication → Option B (new DataSet + new Search). Never fat UNION mixing grains. |
| **Do not change default View** | Option A adds another `AppSearchView`; keep existing `AppSearch.SearchViewId` unless `plan` explicitly switches default. |
| **Prefix** | All APP tables use `@TablePrefix` (default `Plm_`). |
| **Cleanup** | Delete `output/_probe_*` and other output-root scratch files when the run finishes. Keep `source/` probes. |

### Grain rule (from MULTI_VIEW_COVERAGE)

**Same row grain → 1 DataSet + 1 Search + N Views. Different row grain → N DataSets + N Searches (`Search_{Name}_V{ViewId}`).**

Same grain (Grid vs Image Card) → usually Option A.  
Cross grain (list vs list×color) → Option B or a fresh **main** import with `accept-1N`.

## PHASE=A — Discovery (write phase-a, then return)

**Tool rule:** every probe must `execute_sql` with the matching `dataSourceId`. Never claim rows without a tool_result.

Substitute `@SearchTemplateId` / wanted SubItem and MetaColumn lists in the SQL text. Official scripts live in `source/`.

### A0. Verify FieldMapping (APP / `appDataSourceId`)

If `{prefix}FieldMapping` is missing → `ok=false`: run Import DW first.

### A1. Main mode — PLM probe

Run `source/_plm_probe_search.sql` (or equivalent sections) on **PLM**.

| Section | Use |
|---------|-----|
| Search template | Name, `ReferenceViewID`, `BLQueryID` |
| DCU criteria | Criteria fields + tab affinity |
| View columns | Result columns + grid/sub-item enrichment |
| BLQuery | Reference only |
| Tab affinity | JOIN plan ranking |

### A2. Main mode — APP FieldMapping + context

Run `_app_probe_fieldmapping.sql` with `#WantedSubItems` / `#WantedMetaColumns` from PLM §2/§4.  
Run `_app_probe_search_context.sql` for `Tab_{id}` transactions and data sources.

### A3. Coverage (mandatory before JOIN plans)

For each PLM criteria parameter and view column:

| Status | Meaning |
|--------|---------|
| **Mapped** | Exactly one `AppTableName` + `AppColumnName` |
| **Ambiguous** | Same `PlmSubItemId` → multiple APP tables |
| **Missing** | No FieldMapping row |
| **Grid** | `FieldKind = GridColumn` — `gridColumnStrategy` |
| **BuiltIn** | ReferenceId / ReferenceCode → `Plm_ReferenceBasicInfo` |

If criteria mapped < 50% → warn strongly in `phase-a`.

### A4. JOIN plans (main mode — core deliverable)

Cardinality:

| FieldKind | JOIN role | Default |
|-----------|-----------|---------|
| `ReferenceField`, root | `root` | `Plm_ReferenceBasicInfo` |
| `TabField` on tab wide table | `sibling` | `INNER JOIN ON ReferenceId` (1:1) |
| `GridColumn` | `grid` | exclude unless plan says `scalar` / `accept-1N` |

Scoring (show breakdown):

1. Criteria coverage 35%
2. View coverage 35%
3. Tab affinity 15%
4. Header tab bonus 10%
5. Simplicity 5% (fewer tables = higher)

Prune: at most one APP table per `PlmSubItemId` per plan; no grid tables when exclude; prefer dominant `PlmTabId`.

Output **3–10** plans (or fewer with explanation) into `phase-a.joinPlans`.

Checklist for ROOT (do not wait yourself):

```text
[ ] Select JOIN plan: A / B / C / ...
[ ] Grid column strategy: exclude | scalar | accept-1N
[ ] Reference scope: AllReferences | ByTemplateIds [list] | CustomFilter
[ ] Missing fields: ignore | stop and import Template ____ first
[ ] Link target transaction: Tab_{id} for Open/Create
[ ] Search IntegrationId: Search_{Name} (no collision)
[ ] Register in main menu? yes/no
```

### A5. Additional-view mode — APP then PLM

Locate APP Search: `inputs.appSearchIntegrationId` → else `Search_{SearchTemplateId}` → else prior `output/{id}/README.md`. Missing Search → `ok=false`.

Load `SearchID`, `DataSetId`, `QueryText`, existing Views. If this `ReferenceViewId` is already imported → `ok=true` with `nextHint` nothing-to-do (or `ok=false` if ROOT asked re-import without a flag).

PLM: `pdmReferenceView` + `pdmReferenceViewColumn` for `referenceViewId`. Warn if RefTxType family differs.

Classify each View column vs **current** DataSet:

| Class | Meaning |
|-------|---------|
| `Covered` | Already in SELECT |
| `AddColumn` | Table already joined; add to SELECT |
| `AddOneToOneLeftJoin` | One more 1:1 sibling via `LEFT OUTER JOIN` on header/`ReferenceId` |
| `RequiresOneToN` | Grid / row multiply → **cannot** use Option A |
| `Unmapped` | No FieldMapping |

`phase-a` report shape:

```text
Additional View import analysis
PLM SearchTemplateId / ReferenceViewId / names
APP Search # / IntegrationId / DataSet tables
Field coverage: Covered / AddColumn / AddOneToOneLeftJoin / RequiresOneToN / Unmapped
Row-grain: Header1to1 | HeaderTimesGrid | Custom
Recommended: A | B
```

If `RequiresOneToN > 0` → recommend **B**.  
ROOT writes `plan.option` = A | B | C.

## PHASE=B — Generate Blueprint (after ROOT plan)

### Main (or additional-view Option B)

1. Write `source/plmSearchImportConfig.json` (include `plmDataSourceId` / `appDataSourceId`; no secrets).
2. Synthesize `dataSet.queryText`:
   - SELECT resolved view + criteria columns
   - FROM root
   - INNER JOIN 1:1 siblings on `ReferenceId`
   - Grid `scalar`: `(SELECT TOP 1 col FROM grid WHERE grid.ReferenceId = root.ReferenceId)`
   - WHERE from `referenceScope` if set
3. `fieldResolution[]` from FieldMapping (`PlmControlType`, `PlmEntityId`).
4. Split `criteriaFields[]` and `searchView.fields[]`.
5. Copy PLM DCU `OperationID` as-is into `operationId` (`EmAppCriteriaOperatorType` — **not** Wijmo filter enum). Copy `DefaultValue` when non-empty.
6. `entityIntegrationId` = string of `PlmEntityId`. `IsTransRootId = true` on `ReferenceId` when linking. Image: `ControlType = 5` when `PlmControlType = 5`.
7. Write `output/{searchTemplateId}/1_PlmSearch_ImportBlueprint.json`  
   Option B: `1_PlmSearch_ImportBlueprint_V{ViewId}.json`  
   New Search IntegrationId: `Search_{Name}_V{ViewId}`; View: `Search_{Name}_V{ViewId}_View`.  
   Option B: do not auto-register menu unless `plan` says so.

**Schema:** match `source/7_PlmSearch_ImportBlueprint.example.json` (`schemaVersion`, `search`, `dataSet`, `joinPlan`, `fieldResolution`, `criteriaFields`, `searchView`, `linkTargets`, `coverage`).

### Additional-view Option A

Write `output/{searchTemplateId}/2_PlmSearch_SiblingView_{ReferenceViewId}.json`.

**Schema:** match `source/8_PlmSearch_SiblingView.example.json`:

- `mode`: `SiblingViewEnrichDataSet`
