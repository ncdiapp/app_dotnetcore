How App Builder Agent Was Tweaked To Work
========================================

Reference for building similar managed agents (DB SystemPrompt + library tools).


1. Hardcoded prompt → managed SystemPrompt
-----------------------------------------

Do not paste the long hardcoded text. Extract only three things from a working path:

  - Successful tool order → put a numbered main build sequence at the top of the prompt
    (tool names + which result fields to read next)
  - Known failures → short hard rules (do / do not)
  - Core fork → its own section (here: composition document vs lookup;
    where the FK column lives)

Reading order:

  Concepts (a few lines) → Main build sequence → Hard rules → Domain fork →
  Step details (same wording as each tool Description)

Also shrink subscriptions: do not subscribe tools the main sequence never needs.
Gate-tool Descriptions must match that sequence.


2. Matching tools
-----------------

Every tool named in the prompt must be subscribed; Descriptions must not conflict;
tool results must honor what the prompt promises (e.g. if the prompt says use Units,
Units must include nested children — fix the plugin if not; do not only lengthen the prompt).


3. Tuning until it runs clean
-----------------------------

Fix one acceptance script and rerun it. Judge by the AgentLoop tool sequence,
not by chat prose.

  Wrong tool / bad args     → fix subscription or tool Description
  Wrong order / weak bans   → add one prompt line; no essays
  Misleading results / shape → fix the plugin

One issue class per iteration; compare only the new run id.

Same mistake twice or more → prefer a plugin hard rule.


4. Short checklist for a new agent
----------------------------------

  Write successful tool order + key result fields
  → Align subscriptions + Descriptions
  → Write SystemPrompt in the five blocks above
  → Rerun the fixed script until the tool sequence is clean
  → Freeze prompt/subscriptions; note script, success shape, known gaps
