# AI Chat 界面产品化 — 对照建议（待确认）

状态：欢迎页、会话侧栏、版心和顶栏已改。结果面板（第 5 项）还没做。

## 两个项目各自做什么

| 项目 | 角色 | 界面 |
|---|---|---|
| `CGS.BlueCherry.MCP.Client` | 面向用户的聊天产品。React + Vite，独立窗口或嵌入 Portal。后端是 Orleans + Semantic Kernel，用 SignalR 把回答逐字推到浏览器。 | 聊天是主界面：侧栏会话、欢迎页、输入框、右侧 Artifact 面板。 |
| `CGS.BlueCherry.MCP.Server` | MCP 工具和后台管理。管理员在这里登记外部 API。聊天不在这个项目里。 | `wwwroot/admin`：Connector 弹窗（Swagger 地址、鉴权、端点列表、试连）。 |

Client 不解析 Swagger。Server 解析完以后，Client 只是在对话里选用已配置的 Connector 和 Skill。

## 为什么他们的聊天更像成品

他们的界面按「一个 AI 产品」排，我们的界面按「平台里的一个功能页」排。功能上我们并不少：流式回答、工具步骤、追问、向用户提问、表格和图表都有。差在外壳和默认画面。

| 点 | BlueCherry Client | 我们的 Agent Chat |
|---|---|---|
| 第一眼 | 空白会话是欢迎页：问候、Logo、四张起步卡片，输入框一直在底部。 | 打开就是消息区和功能按钮，没有欢迎态。 |
| 会话列表 | 左侧按 Today / Yesterday / 7 days 分组，可折叠，窄屏变成抽屉。 | 会话在管理页里，和平台其它列表同一套表格风格。 |
| 版心 | 消息在中间约 80% 宽，用户气泡和助手气泡分开。 | 助手气泡拉满可用宽度，像表单区块。 |
| 输入 | 底部固定大输入框，模型 / Connector / Skill 在顶栏，发第一条之后锁定。 | 输入在页面底部，控件是平台标准小按钮。 |
| 结果 | 图表、HTML 自动开到右侧可拖拽面板，可放大。 | 表格和图表嵌在消息流里，没有独立结果面板。 |
| 字体和留白 | Inter，大标题，卡片圆角和浅边框，整页几乎只有聊天。 | 跟 API Management、表单页同一套密度，标题和按钮都是后台尺寸。 |

他们的颜色写死在组件里。我们继续用现有主题色，只改结构和留白，不把 BlueCherry 的蓝色搬过来。

## 建议改什么（确认后再做）

只动 Agent Chat 这一页，不动平台其它管理页。

1. **欢迎态。** 新会话没有消息时，中间显示问候和几张起步提示（内容按当前 Skill 配置，没有配置就用通用提示）。底部输入框始终可见。
2. **会话侧栏。** 当前 Skill 的历史会话放在聊天左侧，按日期分组，可收起。窄宽度时改成抽屉。管理用的表格列表可以保留，作为「全部会话」入口。
3. **版心。** 消息列限制最大宽度并居中。用户消息靠右、短气泡；助手消息靠左，不再拉成整行表单块。
4. **顶栏。** 只放会话标题和当前 Skill / 模型。发送、停止留在输入区。
5. **结果面板。** 表格、图表、大段结果可以在右侧打开，宽度可拖。消息里留一张卡片，点开再看全文。这一项比前四项大，可以第二步再做。

不做：不换整套视觉系统，不把管理页改成营销站，不复制他们的 Logo 动画。

## 不在这次界面里做的事

Swagger 地址、解析端点、AI 调用 API，在 BlueCherry 里属于 Server 的 Connector 管理，不属于聊天页。我们已有 OpenAPI Documents 和 MCP Gateway。聊天页只消费已经发布的能力，不在对话里贴 Swagger 地址。
